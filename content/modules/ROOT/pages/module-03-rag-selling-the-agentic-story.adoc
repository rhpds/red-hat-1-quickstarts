== From Direct to Agentic

In the last module you ran *Direct* mode: one question, one retrieval, one answer. Fast and clean. Perfect for a policy lookup where the customer wants a citable answer in a single turn.

Agent mode is a different gear. The model plans, reasons, and calls tools across several turns before it answers. Point it at a knowledge base and it decides on its own when to retrieve and how many times — that's agentic RAG. Give it a web search tool and it can reach past its training data to pull live information. The UI shows the work: each tool call, each result, and the reasoning, all as collapsible sections the customer can open.

Frame it for the customer this way. Direct mode is the fast, single-turn, citable lookup. Agentic mode is multi-step synthesis plus live external data. Same assistant, two speeds — you pick the one that fits the question.

== Exercise 2: The Wow — Live Web Search

This is the headline beat. You'll ask a question the model cannot possibly know from training, show it stumble, then turn on web search and watch it answer correctly with live data. Done well, this is the moment the customer leans in.

=== Ask without web search

. Keep *Processing mode* on *Agent-based*, with the Web Search tool *disabled*.
. Ask a question that lands after the model's training cutoff. Type this and press *Enter*:
+
[source,text]
----
Who won the Super Bowl in 2025?
----

. Read the answer with the customer. The model either guesses wrong or admits it doesn't have up-to-date information. Don't gloss over it — this miss is the setup.

Say it out loud: "Every model has a training cutoff. Ask it about anything after that date and it's flying blind. Watch what happens when we give it a tool to go find out."

=== Ask with web search

. In the left sidebar, enable the *Web Search* tool.
. Ask the exact same question again. Type this and press *Enter*:
+
[source,text]
----
Who won the Super Bowl in 2025?
----

. This time the agent calls the web search tool before answering. Open the reasoning trace and walk the customer through the collapsible steps: the *Tool call* with the query, the *Tool result* with the data it pulled back, the *Agent reasoning*, and the *Final answer*.
+
image::websearch-result.png[The agent returning a grounded web-search answer with a collapsible tool-call trace, role=expand]

The grounded answer comes back correct — the Philadelphia Eagles won Super Bowl LIX, defeating the Kansas City Chiefs 40–22. Deliver the close: "Same question, same assistant. The only difference is we gave it a tool. Now it's answering with live data it never saw in training — grounded, and you can see exactly where it came from."

[IMPORTANT]
====
When you run Agent mode with tools and RAG together, set *Max Tokens* to its maximum so retrieved chunks and tool results aren't truncated. *Max Inference Iterations* caps how many reasoning loops the agent can take — leave headroom so it can finish the job.
====

=== Verify

Without web search the model missed or hedged. With web search it returned the correct, grounded answer and you could open the tool-call trace. That contrast is the wow.

== Positioning: Direct vs. Agentic for the Customer

Your job here isn't to click features. It's narration and framing. You decide what to show first, you anticipate the customer's questions, and you tie every beat back to their world.

Use this as your framing cheat sheet:

* *Direct RAG* — fast, single-turn, citable. Position it for high-volume policy and knowledge lookups: "What's our travel reimbursement limit?" The customer wants one trustworthy answer with a source, instantly.
* *Agentic RAG* — multi-step synthesis plus live external data. Position it for questions that span documents or need information beyond the knowledge base: "Compare these two policies," or anything that touches current events, pricing, or live systems.

The web-search beat is your differentiator. It proves the system answers *live* data the base model never saw — not a canned script, not a static index. In front of a customer that's hard to argue with.

Expect these questions, and have the answers ready:

* "Is it just making this up?" — No. Open the tool-call trace. Every answer shows its retrieval and its sources.
* "Can it use our live systems, not just the web?" — The same tool-calling pattern extends to other tools and APIs. Web search is the one we're showing today.
* "Won't it run forever?" — No. *Max Inference Iterations* caps the reasoning loops. You're in control of the budget.
